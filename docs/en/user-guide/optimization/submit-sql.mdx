This guide describes a single-statement optimization task in the PawSQL web console. Other clients expose different controls, but all require valid SQL and accurate database context.

## Prerequisites

- Access to the intended organization and project;
- permission to create optimization tasks;
- a validated workspace;
- a database engine, version, and schema that match the target;
- sanitized SQL with no embedded credentials.

## Prepare the statement

- Include the complete statement.
- Use delimiters supported by the target database for multi-statement input.
- Make placeholders unambiguous.
- Ensure referenced objects exist in the workspace.
- Remove log text, stack traces, and unrelated content.
- Use a read-only query for the first test.

## Create the task

<Steps>
  <Step title="Open SQL Optimization">Confirm the active organization or project.</Step>
  <Step title="Select a workspace">Verify engine, version, environment, and schema.</Step>
  <Step title="Enter SQL">Paste the complete statement and add a meaningful task name where supported.</Step>
  <Step title="Select analysis options">Enable review, rewrite, index, plan, or validation features as appropriate.</Step>
  <Step title="Submit once">Recheck context and start the task without creating duplicates.</Step>
  <Step title="Open the result">Wait for completion and inspect task details.</Step>
</Steps>

## Parameterized SQL

- Use a placeholder syntax supported by the PawSQL release.
- Provide representative values when plan or performance behavior depends on selectivity.
- Preserve application data types and binding order.
- Replace sensitive literals with safe representative values.
- Convert complex templates to a representative executable statement when necessary.

## Verify success

- [ ] Parsing completed.
- [ ] Engine and version are correct.
- [ ] Schemas, tables, and columns resolved correctly.
- [ ] Statement boundaries were detected correctly.
- [ ] Expected analysis modules ran.
- [ ] No unexplained partial failure remains.

<Tip>
A completed task is not a claim that the SQL is optimal or that every recommendation is safe to apply.
</Tip>

## Troubleshooting

| Symptom | Check first |
| --- | --- |
| Parsing fails | Dialect, version, statement completeness, placeholders, delimiters |
| Object unresolved | Workspace, default schema, identifier case, metadata freshness |
| No rewrite | Applicability conditions and metadata requirements |
| No index recommendation | Existing indexes, object metadata, whether a new index is warranted |
| Task remains queued | Service health, queue, concurrency, task ID |
