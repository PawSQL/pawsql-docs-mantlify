# How PawSQL Rewrites OR Predicates

When a `WHERE` clause combines OR-ed predicates that touch different columns, a single-table plan cannot use an index per branch efficiently. PawSQL's rewrite splits the branches so each can use its own best index.

See the [optimizer rule reference](en/reference/optimizer-rules/opt-or-union) for the canonical description and the formal example.
