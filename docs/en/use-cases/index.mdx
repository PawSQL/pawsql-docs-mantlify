# Use Cases

Pick the scenario closest to your role. Each scenario will grow into a full hands-on tutorial.

| Scenario | Problem it solves | Entry point |
|---|---|---|
| Developer: self-serve SQL optimization in the IDE | Review SQL as you write it, less waiting on a DBA | DBeaver / JetBrains / VS Code plugins |
| CI/CD: a SQL release gate | Run audit in the pipeline and block non-compliant SQL | GitHub Actions / DevOps |
| DBA: batch-govern production slow SQL | Triage the slow-SQL list and produce actionable fixes | PawSQL platform + performance patrolling |
| Migration / 信创: SQL governance while changing databases | Compatibility and standards before switching engines | [SQL Audit](en/user-guide/sql-audit/index) |
| Enterprise: one SQL Governance platform | Centralized rules, roles and release gates | Enterprise / on-premises |
