PawSQL is a **SQL engineering and governance platform** for developers, QA teams, DBAs, and enterprise database governance teams. It helps organizations continuously detect SQL issues, improve performance, and control deployment risk throughout the SQL lifecycle.

From the moment a developer writes a query in an IDE, through CI/CD validation and deployment, to production slow-query governance and enterprise-wide SQL governance, PawSQL brings **SQL review, query rewriting, index recommendation, performance validation, and execution plan analysis** into one platform.

> **Make SQL quality and performance part of the software engineering lifecycle.**

---

## What is PawSQL

SQL performance problems rarely appear out of nowhere in production.

Inefficient query patterns, inappropriate indexes, unintended full table scans, execution plan changes after database migration, and inconsistent SQL development standards can all be introduced during development and later become production performance or stability issues.

PawSQL is designed to shift SQL governance from **reactive optimization after production incidents** to **continuous SQL engineering throughout the software development lifecycle**.

```text
Developer
   │
   ▼
Write SQL
   │
   ▼
SQL Review and Optimization
   │
   ├── SQL Review
   ├── Query Rewrite
   ├── Index Recommendation
   ├── Execution Plan Analysis
   └── Performance Validation
   │
   ▼
CI/CD Quality Gate
   │
   ▼
Production
   │
   ▼
Slow SQL Governance
```

With PawSQL, SQL optimization is no longer limited to post-production DBA work. It becomes part of the engineering workflow.

## One Platform for the SQL Lifecycle

PawSQL covers key stages from development to production.

| Stage | Typical Challenge | How PawSQL Helps |
|---|---|---|
| **Development** | SQL quality depends heavily on individual experience | Analyze and optimize SQL directly in the IDE |
| **Code Review** | Manual review cannot consistently detect all SQL issues | Automate SQL review and optimization analysis |
| **CI/CD** | Risky SQL may reach production | Establish an SQL quality gate |
| **Database Migration** | Database differences may introduce compatibility or performance regressions | Scan and govern migration SQL at scale |
| **Production** | Large volumes of slow SQL require manual DBA effort | Analyze and optimize slow SQL in batches |
| **Enterprise Governance** | Teams, databases, and policies are difficult to standardize | Build a unified enterprise SQL governance platform |

## Core Capabilities

PawSQL goes beyond detecting SQL issues. It helps developers and DBAs understand the problem and identify actionable optimization options.

### SQL Review

PawSQL automatically detects potential risks before SQL reaches production by applying SQL development standards and database best practices.

Typical checks include:

- SQL coding standards
- DDL and DML risks
- Query performance risks
- Index usage issues
- Database best practices
- Enterprise-specific SQL rules

→ [Learn about SQL Review](/en/reference/audit-rules/index)

---

### Query Rewrite

The PawSQL optimization engine can automatically rewrite queries based on SQL semantics and database optimization principles.

For example:

```sql
SELECT *
FROM orders
WHERE customer_id = 1001
   OR customer_id = 1002;
```

can be rewritten as:

```sql
SELECT *
FROM orders
WHERE customer_id IN (1001, 1002);
```

For more complex queries, PawSQL can identify optimization opportunities involving subqueries, joins, aggregation, predicate pushdown, and other transformations while preserving query semantics.

→ [Learn about Query Rewrite](/en/reference/optimizer-rules/index)

---

### Index Recommendation

Index recommendation requires more than identifying columns used in predicates.

PawSQL considers factors such as:

- Filter predicates
- Join predicates
- Sorting and grouping
- Existing indexes
- Column selectivity
- Composite index design
- Database optimizer behavior

By analyzing SQL together with database schema metadata, PawSQL generates candidate index recommendations for the target query workload.

→ [Learn about Index Recommendation](/en/features/index)

---

### Performance Validation

An optimization that is logically sound is not necessarily faster on the target database.

PawSQL can therefore work with the database optimizer to validate candidate optimizations by comparing factors such as:

- Optimizer cost
- Access paths
- Join methods
- Estimated row counts
- Index usage
- Execution plans

This helps teams move from:

**“This query should theoretically be faster.”**

to:

**“The database optimizer also confirms that this plan is better.”**

→ [Learn about Performance Validation](/en/features/index)

---

### Execution Plan Visualization

Complex execution plans often contain many operators and can be difficult to inspect as plain text.

For example:

```text
Nested Loop
 ├─ Index Scan
 └─ Hash Join
     ├─ Sequential Scan
     └─ Bitmap Heap Scan
```

PawSQL Plan Visualizer transforms textual execution plans into a visual execution tree, helping developers and DBAs quickly identify:

- Full table scans
- Expensive operators
- Join strategies
- Index usage
- Cardinality estimates
- Cost distribution

→ [Learn about Execution Plan Visualization](/en/features/index)

## Multi-Database by Design

Enterprise database environments rarely rely on a single database system.

Organizations may operate traditional relational databases, distributed databases, domestic database platforms, and data warehouses at the same time.

Each database may have different SQL dialects, optimizers, indexing mechanisms, and execution plan formats.

PawSQL is designed for **multi-database SQL governance**. It provides a unified analysis entry point while retaining database-specific optimization logic.

## From SQL Optimization to SQL Engineering

Traditional SQL optimization usually begins after a production performance problem occurs:

```text
Performance Issue
       ↓
Find Slow SQL
       ↓
Manual Analysis
       ↓
Manual Optimization
```

PawSQL enables a different workflow:

```text
Write SQL
   ↓
Review
   ↓
Optimize
   ↓
Validate
   ↓
Quality Gate
   ↓
Deploy
   ↓
Continuous Governance
```

SQL is no longer treated as just a string embedded in an application. It becomes an engineering asset that can be **analyzed, validated, governed, and continuously improved**.

That is the core idea behind PawSQL:

> **Make SQL quality and performance part of the software engineering lifecycle.**
