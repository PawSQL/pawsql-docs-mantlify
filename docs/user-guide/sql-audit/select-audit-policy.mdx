创建审核工单时，在「审核策略」下拉框（界面显示为「审核模板」）中选择匹配的策略。选择正确的策略能让同类 SQL 使用一致标准，并避免把不适用于当前数据库或环境的规则加入结果。策略的定义、默认与自定义模板、规则与阈值的管理见[规则与审核策略](/user-guide/rules-policy/)。

## 目标

选择与目标数据库类型、环境和使用场景匹配的审核策略，使同类 SQL 使用一致标准。

## 准备工作

选择策略前，明确目标数据库类型、版本、环境以及审核用途。

## 选择原则

按以下顺序确定策略：

1. 匹配目标数据库类型和版本；
2. 匹配环境，例如开发、测试或生产；
3. 匹配审核用途，例如日常开发、上线变更或专项治理；
4. 确认策略归属、可见范围和维护人；
5. 核对规则级别及参数阈值。

## 检查策略详情

选择策略前至少检查以下信息：

- 支持的数据库类型和版本；
- 策略状态及最近更新时间；
- 启用和停用的规则；
- 每条规则的风险级别；
- 长度、数量、耗时或影响行数等阈值；
- 规则的例外条件；
- 策略是否属于当前项目或组织。

<Warning>
同名策略可能因项目、版本或更新时间不同而包含不同规则。执行正式审核时，不要只根据名称判断策略是否一致。
</Warning>

## 无法选择策略

| 现象 | 处理建议 |
| --- | --- |
| 策略列表为空 | 检查数据库类型、项目、权限和策略状态 |
| 目标策略不可见 | 检查策略可见范围和当前组织 |
| 规则与预期不符 | 核对策略版本、更新时间和数据库版本 |
| 无权修改策略 | 联系项目管理员或策略维护人 |

## 预期结果

所选策略的规则、级别与阈值匹配目标数据库和使用场景，避免无关规则进入审核结果。
