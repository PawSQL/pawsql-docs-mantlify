PawSQL 根据 SQL 条件、连接、排序、分组以及可用数据库上下文生成索引建议。推荐索引是候选方案，不是必须执行的 DDL；应用前应结合现有索引、工作负载和数据库运维要求评估。

## 评估流程

<Steps>
  <Step title="确认上下文完整">
    检查表、列、现有索引和数据库版本是否与目标环境一致。
  </Step>
  <Step title="理解推荐用途">
    确认索引主要服务于过滤、连接、排序、分组还是覆盖查询。
  </Step>
  <Step title="检查重复和合并空间">
    比较现有索引的列、顺序、包含列、过滤条件和索引类型。
  </Step>
  <Step title="验证读取收益">
    创建候选索引后对比执行计划、耗时、扫描量和资源消耗。
  </Step>
  <Step title="评估写入和运维成本">
    检查 DML、存储、创建时间、锁和维护窗口影响。
  </Step>
  <Step title="审核并实施">
    选择适合目标数据库的创建方式，准备回退并持续观察。
  </Step>
</Steps>

## 阅读索引定义

重点确认：

- 目标表和 Schema；
- 索引类型；
- 键列及顺序；
- 排序方向；
- 包含列或覆盖列；
- 过滤条件或部分索引条件；
- 唯一性；
- 分区、本地或全局属性；
- 在线或并发创建选项。

具体能力因数据库类型和版本而异。不要把一种数据库生成的 DDL 直接用于另一种数据库。

## 检查现有索引

| 关系 | 判断重点 | 可能处理方式 |
| --- | --- | --- |
| 完全相同 | 键列、顺序和属性一致 | 通常不应重复创建 |
| 现有索引覆盖推荐索引 | 推荐列是现有索引前导列 | 优先验证现有索引是否已满足需求 |
| 推荐索引覆盖现有索引 | 新索引可能替代较短索引 | 评估其他 SQL 后考虑合并 |
| 列相同、顺序不同 | 过滤选择性、排序和连接需求不同 | 分别验证，不只按列集合判断 |
| 部分重叠 | 各自服务不同工作负载 | 结合全局 SQL 负载评估 |

<Warning>
索引列相同不代表索引等价。列顺序、前导列、包含列、过滤条件、排序方向和索引类型都会影响可用性。
</Warning>

## 评估收益

候选索引可能带来的收益包括：

- 减少全表扫描；
- 降低读取行数；
- 改善连接访问路径；
- 减少排序或临时结果；
- 覆盖查询并减少回表；
- 提高特定过滤条件的选择性。

验证时应使用代表性参数，并关注数据库是否实际选择了新索引。索引已创建但未被使用时，应检查选择率、统计信息、查询写法和优化器成本判断。

## 评估成本

| 成本 | 需要检查的内容 |
| --- | --- |
| 写入成本 | INSERT、UPDATE、DELETE 是否变慢 |
| 存储 | 索引大小、增长速度和副本数量 |
| 创建成本 | 扫描时间、CPU、I/O、日志和临时空间 |
| 锁影响 | 是否阻塞读写，是否支持在线或并发创建 |
| 维护成本 | 重建、统计信息、备份和恢复时间 |
| 分布式成本 | 全局索引、数据复制、分片和网络开销 |

## 实施索引

<Steps>
  <Step title="生成适用 DDL">
    根据目标数据库版本检查索引名称、语法和在线创建选项。
  </Step>
  <Step title="在测试环境创建">
    记录创建耗时、资源、空间和锁行为。
  </Step>
  <Step title="执行性能验证">
    对比计划、耗时和扫描量，同时执行代表性写入测试。
  </Step>
  <Step title="提交变更审核">
    提供受益 SQL、测试证据、容量估算、实施窗口和回退 DDL。
  </Step>
  <Step title="生产实施与观察">
    在批准的窗口创建索引，观察锁、负载、空间和计划变化。
  </Step>
</Steps>

## 不建议创建的情况

- 工作空间没有同步现有索引；
- 推荐索引与已有索引重复；
- SQL 执行频率低且收益有限；
- 表写入压力高，读取收益不足以覆盖维护成本；
- 候选索引过宽或占用空间不可接受；
- 测试环境中数据库没有使用该索引；
- 无法安排安全的创建窗口和回退方案。

## 上线后检查

- 新索引是否被目标 SQL 使用；
- 查询耗时、扫描量和资源是否改善；
- 写入延迟和锁等待是否增加；
- 存储、日志和备份是否受到明显影响；
- 是否出现执行计划回退；
- 原有索引是否仍被其他 SQL 使用。

不要在确认工作负载影响前立即删除被认为“重复”的旧索引。
