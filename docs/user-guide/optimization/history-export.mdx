优化历史用于追踪 SQL 输入、分析上下文、建议和处理结果。通过历史任务可以复核当时的判断、比较不同版本或工作空间中的结果，并生成评审或治理材料。

## 查找历史任务

可以根据当前版本支持的条件进行搜索和筛选，例如：

- 任务名称或编号；
- 创建人；
- 创建时间；
- 组织或项目；
- 工作空间；
- 数据库类型；
- 任务状态；
- SQL 关键字或指纹；
- 是否生成重写或索引建议。

多个筛选条件通常同时生效。没有结果时，应检查时间范围、当前项目和工作空间，而不是重复创建任务。

## 查看历史任务

打开历史任务后，建议核对：

- 任务创建时间；
- PawSQL 和数据库版本；
- 当时使用的工作空间；
- SQL、参数和 Schema；
- 元数据来源及更新时间；
- 审核、重写、索引和计划结果；
- 任务是否部分失败；
- 采用、拒绝或验证记录。

<Note>
历史任务反映当时的 SQL 和数据库上下文。当前工作空间已经更新，并不代表历史任务会自动重新分析。
</Note>

## 何时重新运行

以下情况建议创建新任务，而不是直接复用旧结论：

- SQL 已修改；
- 数据库版本升级；
- 表结构、约束或索引变化；
- 数据规模或分布明显变化；
- 参数特征变化；
- PawSQL 优化引擎或规则版本更新；
- 需要重新获取执行计划或性能数据。

新旧任务之间应保留关联说明，便于比较和审计。

## 导出内容

根据产品版本和权限，导出可能包含：

- 任务基本信息；
- 原始 SQL；
- 审核问题；
- 重写 SQL；
- 索引推荐；
- 执行计划和可视化；
- 性能验证结果；
- 处理状态和备注。

## 导出前检查

- [ ] 选择了正确的任务和时间范围。
- [ ] 确认导出的是单条任务还是筛选结果集合。
- [ ] SQL、对象名和报告内容已经按用途脱敏。
- [ ] 文件格式满足接收方需求。
- [ ] 当前用户有权导出和共享这些数据。
- [ ] 报告中标明数据库、工作空间和分析时间。

<Warning>
优化报告可能包含完整业务 SQL、表名、列名、执行计划和数据规模信息。共享前应进行数据分类和脱敏，不要通过公开链接传播生产报告。
</Warning>

## 共享结果

推荐共享任务链接或受控报告，并附上：

- 任务目标；
- 数据库和环境；
- 主要建议；
- 验证条件；
- 采用结论；
- 风险和回退方式；
- 负责人和下一步。

不要只发送一段重写 SQL 或索引 DDL，而不附带原始问题和验证依据。

## 结果留存建议

| 使用场景 | 建议保留内容 |
| --- | --- |
| 代码评审 | 原始与重写 SQL、规则说明、正确性验证 |
| 索引变更 | 推荐依据、计划对比、容量和写入影响 |
| 生产治理 | 基线、性能指标、实施时间和上线观察 |
| 审计追踪 | 任务编号、人员、结论、审批和版本信息 |

## 常见问题

### 找不到历史任务

检查组织、项目、时间范围、工作空间和任务权限。任务也可能已按数据保留策略归档。

### 历史建议与当前结果不同

比较 SQL、PawSQL 版本、数据库版本、参数、元数据和执行计划生成时间。

### 导出文件内容不完整

检查任务是否部分完成、当前角色权限、选择的导出范围和文件格式能力。
