一个 SQL 优化任务可能同时产生规范问题、SQL 重写、索引推荐、执行计划分析和性能验证结果。这些结果从不同角度描述同一条 SQL，应结合阅读，而不是分别机械采用。

## 建议阅读顺序

<Steps>
  <Step title="确认分析上下文">
    检查数据库类型、版本、Schema、工作空间和 SQL 是否正确。
  </Step>
  <Step title="确认解析完整性">
    查看 SQL 和对象是否全部识别，是否存在跳过或部分失败。
  </Step>
  <Step title="先处理高风险问题">
    优先查看阻断、严重以及可能影响数据安全和稳定性的审核问题。
  </Step>
  <Step title="评估重写建议">
    比较原始 SQL 与重写 SQL，阅读规则依据和适用条件。
  </Step>
  <Step title="评估索引建议">
    检查推荐索引、现有索引、写入成本和适用查询范围。
  </Step>
  <Step title="查看验证证据">
    对比执行计划、预估代价或实测指标，判断建议是否带来实际收益。
  </Step>
</Steps>

## 结果类型

| 结果 | 主要回答的问题 | 使用方式 |
| --- | --- | --- |
| 审核问题 | SQL 是否违反规范或存在风险？ | 决定是否必须修改或进入复核 |
| SQL 重写 | 是否存在语义等价的更优写法？ | 对比语义、复杂度和执行计划 |
| 索引推荐 | 是否可以通过访问路径改善性能？ | 检查重复、覆盖范围和维护成本 |
| 执行计划 | 数据库准备如何执行 SQL？ | 定位扫描、连接、排序和数据移动等成本 |
| 性能验证 | 优化前后是否有可量化差异？ | 使用代价或实测指标支持决策 |

## 阅读审核问题

每个问题建议关注：

- 风险级别；
- 问题所在语句和位置；
- 规则说明；
- 触发条件；
- 修改建议；
- 当前数据库是否适用；
- 是否需要申请例外。

规则未触发不代表 SQL 没有性能问题。审核规范和优化建议解决的问题并不完全相同。

## 阅读 SQL 重写

比较原始 SQL 和重写 SQL 时，重点检查：

- 返回列、数据类型和列顺序；
- `NULL` 语义；
- 重复行与去重行为；
- 过滤和连接条件；
- 聚合、排序、分页和窗口函数；
- 数据修改范围；
- 目标数据库兼容性。

不要只因为重写 SQL 更短或预估代价更低就直接采用。

## 阅读索引推荐

需要同时检查：

- 推荐索引所在表；
- 索引列及其顺序；
- 是否包含额外覆盖列；
- 与现有索引的重复或包含关系；
- 受益 SQL 的执行频率和业务重要性；
- 对写入、存储和维护的影响。

## 处理优先级

| 优先级 | 典型情况 |
| --- | --- |
| 高 | 数据安全风险、可能全表修改、核心高频慢 SQL、明显错误计划 |
| 中 | 稳定性风险、频繁扫描、可验证的重写或索引收益 |
| 低 | 可维护性提示、低频 SQL、收益不确定或变更成本较高 |

## 记录处理结论

建议为每项建议记录：

- 采用、调整、拒绝或待验证；
- 负责人；
- 判断依据；
- 测试环境和参数；
- 执行计划或性能数据；
- 计划上线时间；
- 回退方式。

<Warning>
建议的风险等级、预估代价和性能收益是决策依据，不是自动发布指令。生产变更仍应遵循审核和发布流程。
</Warning>
