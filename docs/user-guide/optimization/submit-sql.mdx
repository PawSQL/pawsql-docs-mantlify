本页说明如何通过 PawSQL Web 控制台创建单条 SQL 优化任务。其他入口的操作形式不同，但都需要提供 SQL 和正确的数据库上下文。

## 前提条件

- 可以登录 PawSQL 并进入正确的组织或项目；
- 具有创建 SQL 优化任务的权限；
- 已创建或获得一个可用工作空间；
- 工作空间的数据库类型、版本和 Schema 与目标 SQL 一致；
- SQL 已移除密码、令牌和不必要的敏感数据。

## 准备 SQL

提交前建议检查：

- SQL 语句完整；
- 多条语句使用目标数据库支持的分隔方式；
- 参数占位符清晰，不会被误认为列名或关键字；
- SQL 引用的表、视图和列存在于工作空间；
- 未把应用日志、异常堆栈或其他非 SQL 文本一起粘贴；
- 测试 SQL 不会因为误执行而修改生产数据。

## 创建优化任务

<Steps>
  <Step title="进入 SQL 优化">
    从产品导航打开 SQL 优化页面，确认当前组织或项目。
  </Step>
  <Step title="选择工作空间">
    核对数据库类型、版本、环境和 Schema。不要只根据名称判断。
  </Step>
  <Step title="输入 SQL">
    粘贴完整 SQL。当前版本支持任务名称或说明时，填写能够识别业务用途的信息。
  </Step>
  <Step title="配置分析选项">
    根据需要选择审核、自动重写、索引推荐、执行计划或性能验证。可用选项取决于数据库和授权。
  </Step>
  <Step title="提交任务">
    再次确认 SQL 和工作空间，然后启动分析。避免连续重复提交。
  </Step>
  <Step title="等待任务完成">
    查看任务状态；完成后进入结果详情。
  </Step>
</Steps>

## 参数化 SQL

应用代码中的 SQL 可能包含命名参数、问号占位符或模板表达式。提交时应：

- 使用 PawSQL 当前版本支持的参数形式；
- 必要时提供具有代表性的参数值；
- 保持参数数据类型与应用运行时一致；
- 不使用真实身份证号、手机号、账户号等业务数据；
- 模板 SQL 无法解析时，先转换为一条可执行的代表性 SQL。

参数值会影响选择率和执行计划。性能验证时，应选择能够代表常见场景和边界场景的参数。

## 确认任务成功

任务完成后至少检查：

- [ ] SQL 解析成功。
- [ ] 数据库类型和版本正确。
- [ ] 表、列和 Schema 识别正确。
- [ ] 任务没有被错误截断为多条或少条语句。
- [ ] 审核、重写、索引或计划模块按预期执行。
- [ ] 结果页面没有未处理的部分失败。

<Tip>
任务状态为“已完成”表示分析结束，不表示 SQL 已经最优，也不表示所有建议都适合直接采用。
</Tip>

## 常见问题

### SQL 无法解析

检查数据库方言、版本、语句完整性、参数占位符、引号和分隔符。可以先删除与问题无关的语句，构造最小复现 SQL。

### 表或列无法识别

检查工作空间、默认 Schema、对象大小写以及元数据是否已经更新。

### 没有生成重写结果

没有重写结果不等于分析失败。当前 SQL 可能未满足重写条件，或相关规则需要更完整的元数据。

### 没有索引推荐

SQL 可能不需要新索引，或工作空间缺少表和已有索引信息。先检查结果说明和数据库上下文。

### 任务长时间等待

记录任务编号，检查任务队列、服务状态和系统资源。不要连续创建相同任务。
