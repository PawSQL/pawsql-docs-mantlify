聚合去重后得到治理清单，下一步是对其中的慢 SQL 发起优化。慢查询页提供行级与批量两种入口，批量操作可一次对多条慢 SQL 发起优化。

## 批量操作

勾选表格中的慢 SQL（可跨页多选），点击「批量操作」展开操作菜单：

<Frame caption="批量操作菜单：优化、批量 AI 优化、忽略">
  ![批量操作菜单](/images/performance/patrol-batch-operate-menu.png)
</Frame>

| 操作 | 说明 |
| --- | --- |
| 优化 | 对选中的慢 SQL 创建优化任务，生成 SQL 重写与索引推荐 |
| 批量 AI 优化 | 对选中的慢 SQL 发起 AI 智能优化 |
| 忽略 | 将选中的慢 SQL 标记为忽略，从治理清单中排除 |

## 行级操作

每条慢 SQL 的「操作列表」列也提供三个动作：

| 按钮 | 说明 |
| --- | --- |
| 优化 | 对单条慢 SQL 创建优化任务 |
| AI 智能优化分析 | 对单条慢 SQL 发起 AI 智能优化分析 |
| 标记忽略 | 将该 SQL 标记为忽略 |

## 创建优化任务

点击「优化」后进入「新建查询优化」页，针对选中的查询（页面标题会显示数量，如「为 1 个查询创建优化」）配置优化参数：

<Frame caption="新建查询优化：基础配置、优化验证、索引优化与规则配置">
  ![新建查询优化](/images/performance/patrol-new-analysis.png)
</Frame>

### 基础配置

| 配置项 | 说明 |
| --- | --- |
| 优化ID | 本次优化的唯一标识，默认按时间自动生成，可修改 |
| 仅索引推荐 | 勾选后不重写 SQL，只基于原 SQL 推荐索引 |

### 优化验证

| 配置项 | 说明 |
| --- | --- |
| What-If 验证 | 连接到验证数据库进行 What-If 性能验证（默认开启） |
| 是否更新统计信息 | 进行 What-If 验证前是否更新统计信息 |
| Analyze | `explain` 时是否实际执行 SQL |

### 索引优化

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 和已有索引去重 | 开启 | 是否与工作空间中已有索引去重 |
| 覆盖索引推荐 | 开启 | 是否启用覆盖索引推荐（避免回表，可能占用额外磁盘） |
| 覆盖索引最大列数 | `4` | 超过此列数不执行覆盖索引推荐 |
| 索引最大列数 | `4` | 推荐索引的最大列数 |
| 单表索引数 | `5` | 每张表最大索引数量，超出时提示清理 |
| 最大占用空间 | `1000` | 所有推荐索引占用的最大空间（MB） |

### 规则配置

选择规则模板（如「MySQL数据库审核模板」），或通过内联规则配置逐条启用/禁用规则、调整阈值。规则按「对象设计 / 对象操作 / 数据操作」三大类组织，并可按级别（提示 / 警告 / 严重 / 未启用）筛选。选择模板后使用模板规则，忽略内联配置。

## 提交优化

核对配置后点击「创建优化任务」。优化由服务端执行，完成后在慢查询页的「优化状态」「最近优化」「性能提升」列看到结果。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 批量操作无可选动作 | 是否已勾选慢 SQL |
| 优化任务长时间等待 | 任务队列、并发限制、分析服务状态 |
| 性能提升显示 N/A | 是否尚未优化，或优化任务是否完成 |
