审核策略决定 PawSQL 检查什么，质量门禁决定检查结果如何影响交付。结果回传则把门禁结论、问题摘要和完整报告入口带回开发人员当前使用的平台。

## 目标

将 PawSQL 审核结果转换为通过、警告或阻断结论，并反馈到代码仓库和流水线。

## 准备工作

准备一份已发布的审核策略，明确阻断条件和异常行为。

## 推荐决策表

| 条件 | 默认结论 | 建议处理 |
| --- | --- | --- |
| 无 SQL 变更 | 跳过 | 正常结束并记录原因 |
| 无违规或仅提示 | 通过 | 返回审核摘要 |
| 存在警告级问题 | 警告或阻断 | 由团队风险策略决定 |
| 存在严重级问题 | 阻断 | 修复后重新提交 |
| SQL 解析失败 | 阻断 | 检查方言、脚本和工作空间 |
| 缺少必要上下文 | 阻断 | 补充 DDL 或修复数据库连接 |
| PawSQL 服务异常 | 按异常策略 | 阻断、有限重试或转人工 |

## 配置流程

<Steps>
  <Step title="确定作用范围">指定仓库、分支、目录、数据库类型和发布阶段。</Step>
  <Step title="选择审核策略">使用经过验证的规则集，并记录每次运行实际使用的策略版本。</Step>
  <Step title="定义阻断条件">按严重级别、指定规则、解析错误或问题数量设置阈值。</Step>
  <Step title="定义异常行为">明确超时、认证失败和服务不可用时采用失败关闭、失败开放还是转人工。</Step>
  <Step title="建立豁免机制">要求记录原因、审批人、作用范围和到期时间。</Step>
  <Step title="配置结果反馈">选择提交状态、合并请求评论、流水线结果或审核报告等渠道。</Step>
</Steps>

## 建议回传字段

| 字段 | 说明 |
| --- | --- |
| 门禁结论 | 通过、警告、阻断或系统异常 |
| 工单状态 | 等待、运行、完成、失败或超时 |
| 问题统计 | 按严重级别或规则分类 |
| SQL 定位 | 文件、语句序号和行号 |
| 策略版本 | 支持重现当时的审核结论 |
| PawSQL 工单 ID | 支持跨系统追踪 |
| 报告链接 | 查看完整问题、建议和处理记录 |

## 状态映射

| PawSQL 结果 | 代码平台或流水线状态 |
| --- | --- |
| 等待或运行中 | Pending / Running |
| 审核通过 | Success |
| 仅有非阻断问题 | Success with warnings 或 Neutral |
| 命中阻断条件 | Failed |
| 系统异常或超时 | Error，按异常策略决定是否阻断 |
| 无 SQL 变更 | Skipped 或 Success |

新的提交到达后，旧工单结果应标记为过期，只有最新提交对应的工单可以满足合并条件。重复运行同一提交时，应更新既有检查或机器人评论，避免重复消息。

## 预期结果

审核结果被转换为通过、警告或阻断结论，并回传门禁结论、问题摘要和报告入口。

## 验证

确认状态映射正确，且重复运行更新既有检查而非产生重复消息。

<Warning>
  失败开放必须同时产生告警和审计记录。任何人工豁免都应有明确审批人、原因、范围和有效期。
</Warning>
