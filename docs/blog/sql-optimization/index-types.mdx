数据库索引是一种用于加快查询速度的数据结构，作用类似于书籍的目录，可以帮助快速定位到表中某一行或某些行。索引通常由一组索引键（索引字段）构成，这些键的值被存放在特定数据结构中，以便快速查找。

## 按实现方式分类

从索引的实现方式看，常见的有：

- B+ 树索引
- Hash 索引
- 空间索引（例如 R 树）
- 全文索引
- Bitmap 索引

每种索引适用于不同的数据类型和查询类型，应根据具体需求选择。

### B+ 树索引

B+ 树是一种平衡树，每个节点包含一定数量的关键字和指向子节点的指针，支持快速的查询和排序。B+ 树索引适用于各种数据类型，并支持范围查询与排序，因此在许多数据库系统中被广泛使用。

![B+ 树结构示意](/images/blog/index-types-b-plus-tree.png)

*图片来源：Wikipedia*

数据库执行查询时，先在 B+ 树索引中搜索包含所需关键字的节点，再通过指针找到包含该关键字的数据记录。如果是范围查询，还可以查找包含范围内关键字的节点，返回所有符合条件的数据记录。

**优点**

- 支持快速的查询和排序
- 支持多种数据类型，可索引数值型、字符串型和日期/时间型数据
- 作为平衡树，可以处理大量数据

**缺点**

- 插入或删除数据时可能需要重新平衡，因此写操作可能变慢
- 更新数据需要删除原记录并创建新记录，可能消耗较多时间和空间

### Hash 索引

Hash 索引基于哈希表，使用哈希函数将数据映射到哈希表中的桶（bucket）。

![Hash 表结构示意](/images/blog/index-types-hash-table.png)

*图片来源：Wikipedia*

执行查询时，数据库用哈希函数计算关键字的哈希值，然后在哈希表中查找具有相同哈希值的数据记录。如果多条记录哈希值相同，还需要用比较运算符进一步确认。

**优点**

- 查询非常快，可以直接访问桶
- 对等值查询特别有效
- 无需排序，不消耗额外的排序时间和空间

**缺点**

- 不支持范围查询和排序
- 哈希冲突可能导致查询变慢
- 适用数据类型有限
- 插入、更新、删除可能需要重新散列

### 空间索引

空间索引专门用于处理空间数据，常见于地理信息系统（GIS）和空间数据库，用于快速查询空间数据的位置和几何关系。

![R 树结构示意](/images/blog/index-types-r-tree.png)

*图片来源：Wikipedia*

空间索引通常使用网格结构（格网、网格图或四叉树）把空间数据划分为许多小的网格单元，每个单元存储其中的一个或多个数据点，再用空间算法快速查询其他单元，确定数据点之间的几何关系。

**优点**

- 可以快速查询空间数据的位置和几何关系
- 对矩形范围、圆形范围等空间范围查询非常有效

**缺点**

- 实现比较复杂，需要空间算法方面的知识
- 不适用于非空间数据
- 数据量很大时可能占用大量内存

### 全文索引

全文索引用于快速搜索文本内容，可以在数据库中搜索文本字段，也可以在文档管理系统中搜索文件内容。它通常先对文本分词，再用倒排索引等结构存储分词结果，以便快速查询搜索词。

**优点**

- 可以快速搜索文本内容
- 支持模糊词搜索
- 可以处理多语言文本

**缺点**

- 不适用于非文本数据
- 文本数据较大时可能消耗大量计算和存储资源
- 可能存在误判

### Bitmap 索引

Bitmap 索引通过把数据存储为二进制位映射来加速查询：每个位代表一条数据记录是否符合某个条件，为 1 表示符合，为 0 表示不符合。

**优点**

- 高效：可以很快执行大量逻辑运算
- 空间效率高：只需要存储 0 和 1 的二进制位

**缺点**

- 数据更新困难：数据变更时需要重新生成整个 Bitmap 索引
- 仅适用于取值类别有限的数据，例如城市、性别

因此 Bitmap 索引通常用于不同取值较少的列。

## 按其他维度分类

### 唯一索引

从唯一性角度，索引可分为唯一索引和非唯一索引。唯一索引用于保证某列的唯一性约束，通常用于实现主键约束和唯一性约束；数据库一般会为主键或唯一性约束自动创建唯一索引。

唯一索引不仅能提高查询效率，还起到数据校验的作用，避免重复数据。代价是每次插入或修改数据都要检查是否违反唯一性约束。

### 聚簇索引

从聚簇率角度，索引可分为聚簇索引和非聚簇索引。聚簇索引的索引键排列顺序与表中数据的排列顺序一致；由于表数据只能按一种方式排序，每个表只能有一个聚簇索引。

较先进的数据库优化器也会计算非聚簇索引的聚簇率，用于评估回表时的磁盘 IO 代价。聚簇率小的索引回表时会引起磁盘 IO 抖动，明显影响查询性能——一般来讲，聚簇率越大，磁盘 IO 代价越小。

聚簇索引有两种实现方式：

- 聚簇索引与表数据存储在一起，索引树的每个叶子节点存储一个完整的表行，以 MySQL 的 InnoDB 引擎和 SQL Server 为代表
- 聚簇索引与表数据分离，可以先有表再定义聚簇索引，以 DB2、PostgreSQL、Oracle 为代表

聚簇索引的优势是减少磁盘 I/O 次数，从而提高查询性能；缺点是插入新数据时可能需要移动数据页或重新组织索引，对性能产生负面影响。

### 二级索引

从是否为主键的角度，索引可分为主键索引和二级索引。主键索引只能有一个，二级索引可以有多个。

### 组合索引

从包含的索引列数目看，索引可分为单列索引和组合索引。组合索引可以满足多种查询条件，从而节省索引空间与维护代价。组合索引遵循最左前缀匹配原则，详见[如何创建高效的索引](/blog/sql-optimization/efficient-index-design)。

### 函数索引

函数索引（表达式索引）基于函数或表达式构建，使用计算好的值作为索引列，可以在不修改应用程序的情况下提高查询性能：

```sql
alter table lineitem add index idx(DAYOFMONTH(l_shipdate));
```

> `DAYOFMONTH` 是 PostgreSQL 自带函数，用于从日期中取出天数。

### 条件索引

条件索引（部分索引，Partial index）建立在一个表的子集上，该子集由条件表达式定义，索引只包含满足条件的行：

```sql
create index l_partkey_idx on lineitem(l_partkey) where l_shipdate > '2022-01-01';
```

## 小结

- **B+ 树索引**：最常用，具有平衡树性质，可以有效维护大量数据，适用于大部分数据类型，尤其是数值型和字符串型，并支持区间查询；由于有序性，还可以省去 SQL 中的排序操作。
- **Hash 索引**：适用于精确匹配查询，查询效率高，但不支持范围查询和排序。
- **空间索引**：用于空间数据的查询与管理，例如 R 树。
- **全文索引**：用于文本数据的搜索与排名。
- **Bitmap 索引**：用位图维护索引，适用于处理大量布尔数据的查询。
