## 先识别问题

先区分无法连接数据库、无法完成 SQL 分析、优化结果不符合预期，以及文档缺失。它们需要不同的复现材料；不要把连接失败直接解释为数据库不受支持。

## 缩小问题范围

- 兼容性：查看[支持的数据库](/getting-started/supported-databases)，核对数据库版本和所用能力；部分支持条目应结合实际版本确认。
- 优化结果：记录原 SQL、建议 SQL、索引变化以及验证方式。是否等价与是否更快是两个不同问题。
- 操作流程：先核对[结果阅读说明](/getting-started/quickstart)，确认查看的是审核、重写还是索引建议。

## 准备复现材料

整理 PawSQL 版本、数据库类型与版本、使用的组件/入口、操作步骤、预期结果、实际结果和错误时间。SQL 问题附最小表结构、脱敏 SQL 与必要的执行计划；保留 NULL、重复值等影响语义的特征。

不要提交密码、连接令牌、生产数据或含敏感常量的原始日志。具体报障入口与服务承诺应以所在版本的服务说明为准，本文不预设联系方式。

## 验证处理结果

在隔离测试环境重现原问题，再重复修复后的步骤。查询重写优化要同时检查结果集语义与性能；一次运行变快不代表生产负载下必然更快。记录仍然存在的限制，未复现成功时不要把问题标记为已解决。
